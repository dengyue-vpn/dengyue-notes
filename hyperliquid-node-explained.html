「Hyperliquid 节点」是什么：自己跑节点和找线路节点各指什么

本文原载于登月VPN 博客，内容与后续更新以原文为准。

「Hyperliquid 节点」有两个意思：开发者用高配服务器自己跑的链上节点，和 VPN、机场里的线路节点。手动交易只需要后者。

先确认你要的是哪一种，再往下看对应的部分。

两种「节点」对照

Hyperliquid 链上节点 线路节点
是什么 运行 Hyperliquid 官方节点程序，同步整条链的数据 代理服务器，把你的网络连接转到境外
给谁用 做量化、数据分析、跑验证者的开发者 用网页或 App 交易、看盘的普通用户
需要什么 一台高配服务器，自己运维 一个订阅，在客户端里选线路
交易时必需吗 官方文档没把它列为交易前提，普通下单走官方 API 用来改善你家到 Hyperliquid 的连接

第一种：自己跑 Hyperliquid 节点

Hyperliquid 官方文档的「Nodes」页把节点分为非验证者（non-validator）和验证者（validator）两类，安装步骤放在官方 GitHub 仓库 hyperliquid-dex/node。以下内容 2026-10-12 核对该仓库 README。

配置要求：

角色 vCPU 内存 硬盘
非验证者节点 16 vCPU 128GB 500GB SSD
验证者节点 32 vCPU 128GB 1TB SSD

另外几条硬门槛：

  • 系统目前只支持 Ubuntu 24.04。
  • 4001、4002 端口要对公网开放，用于节点之间同步数据。
  • README 写明想要最低延迟，节点放在日本东京。
  • 默认设置下每天产生约 100GB 日志，要定期归档或删除。

跑起来能得到什么。 非验证者节点从其他节点实时同步数据，启动时可以加参数，把成交、成交回报、每笔订单状态、订单簿逐笔变化写到本地文件，也可以开一个本地信息服务。README 的说法是，本地信息服务有助于应对限频，也减少对外部运营方的依赖。不过它目前只支持一部分完全由本地状态决定的查询，不能整个替代公开 API。

什么人值得跑。 需要完整的逐笔数据做回测或分析、程序频繁查询公共 API 碰到限频、或者打算做验证者的人。只是手动开仓平仓的话，这台高配服务器的月租和运维时间基本用不上。验证者还要先在链上注册，并和其他验证者保持较低的往返延迟，门槛更高。

普通程序化交易不一定要节点。 Hyperliquid 公开 API 的主网地址是 https://api.hyperliquid.xyz，官方有 Python SDK，社区有 Rust、TypeScript SDK，CCXT 也已接入。轻量的下单脚本直接调公开 API 就行。公开 API 的限频按 IP 计算，具体数字和对线路选择的影响见 Hyperliquid 用哪条线路。

第二种：找能用 Hyperliquid 的线路节点

如果你搜这个词是因为网页打不开、看盘断线，想找一条合适的线路，要选的是线路节点，按你家宽带的运营商选：

你的宽带 推荐线路 也可选
电信 韩国【电信直连】01 香港【电信直连】01、日本【电信直连】01
联通 韩国【联通直连】01 香港【联通直连】01、日本【联通直连】01
移动 韩国【移动直连】01 香港【移动直连】01、日本【移动直连】01

韩国、香港、日本的线路都推荐给 Hyperliquid。香港离大陆近，延迟更低，所有线路都按 1 倍扣流量。

节点放东京，不代表线路也要选日本。 README 推荐东京，指的是链上节点和其他节点之间的同步。你在国内用网页交易，晚高峰的拥堵主要出在「你家 → 线路服务器」这一段，所以先按运营商选直连线路，再看地区。

同时用几家交易所的话，可以对照 交易所用哪条线路：10 家交易所按电信、联通、移动选线，挑一条几家都推荐的固定用。账户和地区规则以平台为准，固定一个出口国家、少来回切换更稳妥。线路选好后晚高峰怎么自己测，见 看盘断线和延迟怎么测。

两种都要的情况

有人在云服务器上跑程序，自己在家又用网页看盘。程序那一边按上面的节点要求或公开 API 规则部署，家里看盘那一边按运营商选线路节点。两者互不替代：节点解决的是数据从哪来，线路解决的是你家能不能顺畅连上。
