GitHub 上的机场推荐列表能信吗：怎么核对

本文原载于登月VPN 博客，内容与后续更新以原文为准。

GitHub 上的机场推荐列表可以当线索，不能直接当结论。先用提交记录、链接和 Issues 核对它是不是最近维护过、和机场有没有推广关系，再决定要不要买月付自己测。

核对分 5 步：看最近一次改了内容的提交，看链接是不是推广链接，看有没有写测试方法，看 Issues 和星标，再分清推荐列表和免费节点。星标多、标题写着「2026 最新」，都说明不了内容是最近核对过的。

我们是登月VPN，自己也卖线路，所以这篇讲怎么核对，不点评任何一个具体仓库。商业测评网站的排行榜怎么读，另见 VPN 排行榜怎么读。

GitHub 列表和测评网站有什么不同

搜「机场推荐 github」，找到的大多是个人或小团队维护的 README：一张表，列着机场名字、价格、节点地区，后面跟一个注册链接。它和测评网站有三点不一样：

方面 GitHub 列表 测评网站
改动记录 每次修改都留在提交历史里，人人可查 通常只看到页面上写的更新日期
推广披露 很少有单独的披露页，要自己看链接 一般有披露页或页脚说明
测试方法 多数只给结论，少数附测速截图 部分有方法论页

提交历史公开，是 GitHub 列表最大的好处。下面的核对方法主要就是用好这一点。

第一步：看最近一次「改内容」的提交

打开仓库，点文件列表上方的提交记录（commits），看最近几次提交改了什么。

  • 只改了标题里的年份或日期：内容不一定动过。把「2025」改成「2026」也算一次提交，仓库首页显示的最近提交时间也会跟着变。
  • 改了表格里的价格、地区、链接：说明维护者确实在跟进。点开那次提交，看改了哪几行。
  • 很久没有提交：机场的价格、线路、运营状态变化很快，半年没动过的列表，参考价值有限。

还要知道一点：在自己电脑上做的提交，日期取自那台电脑的时间，而且可以手动改。作者日期可以用 --date 选项指定，提交日期可以用 GIT_COMMITTER_DATE 环境变量指定（Git 官方文档 git-commit，2026-10-13 核对）。所以日期只能说明「有人这样记录」，要配合改动内容一起看。

第二步：看链接是不是推广链接

把鼠标放在注册链接上，或者复制出来看完整地址：

  • 地址里带 aff=、code=、ref=、invite 之类的参数，通常是推广链接，点进去注册，维护者可以拿到返佣。
  • 链接先跳到一个短链或中转页，再到机场官网，也常见于推广。

推广本身很普遍，不代表列表一定有偏差。要注意的是：README 里有没有写明「链接含推广」？如果每个机场都带推广链接、却完全没写，你就要把排序当成作者的选择，别当成测出来的结果。

第三步：看有没有测试方法

很多列表只写「速度快」「稳定」「推荐」。能复核的写法至少要写清在哪测（大陆家宽还是海外服务器）、什么时段、哪个运营商、测了几次，这几项的逐项读法见 VPN 排行榜怎么读。

列表里附了测速截图的，按 一篇机场实测缺少哪些信息就难以复核 那 9 项逐项对一下。什么方法都没写的，只能当「有这几家」的名单用。

第四步：看 Issues 和星标

Issues 是读者给仓库提问题的地方。翻一翻已关闭和未关闭的：

  • 有没有人反馈「这家跑路了」「链接失效了」「价格变了」？
  • 维护者有没有回复、有没有据此修改列表？
  • 仓库是不是关闭了 Issues？关了就少了一个读者反馈的渠道。

星标 只能当热度参考。GitHub 官方说明里，星标用来收藏仓库、发现相似项目，也表示对维护者的认可（GitHub 文档：用星标保存仓库，2026-10-13 核对）。它反映的是多少人收藏过，说明不了有多少人用过列表里的机场。GitHub 的《可接受使用政策》明确禁止自动刷星、刷关注这类「排名滥用」（GitHub Acceptable Use Policies 第 4 节，2026-10-13 核对），平台禁止，说明确实有人会这么做。星标很多、Issues 却很冷清，就要多留个心。

第五步：分清「推荐列表」和「免费节点」

搜 GitHub 时，还会碰到另一类仓库：直接贴出免费订阅链接或节点。它和推荐列表性质不同：

  • 推荐列表只是介绍机场，你最后还是去机场官网买。
  • 免费节点仓库给的是现成的连接，你的流量会经过一台你不知道是谁在运营的服务器。

免费节点的限制和风险，我们在 免费机场和付费订阅怎么选 里单独讲过。登录交易所、钱包这类账户，尽量用你知道是谁在运营、出了问题能找到人的服务。

核对清单

# 核对项 怎么看 没通过意味着什么
1 最近一次改内容的提交 点开提交，看改了表格还是只改了年份 内容可能早就过时
2 提交频率 看最近几个月有没有持续改动 机场变化没人跟进
3 推广链接 看链接参数和跳转 排序可能跟返佣有关
4 推广披露 README 里有没有写 看不出作者和机场的利益关系
5 测试方法 地点、时段、运营商、次数 「推荐」只是作者的个人感受
6 Issues 反馈 有没有跑路、失效的反馈和回复 少了读者纠错的渠道
7 机场本身的记录 域名、官网公告、网页存档 列表上的「老牌」可能无从核对
