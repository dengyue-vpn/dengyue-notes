交易所网址打不开但 App 能用：DNS 解析问题怎么判断

本文原载于登月VPN 博客，内容与后续更新以原文为准。

App 能用、网址打不开，先怀疑 DNS：浏览器把交易所域名解析到了错误地址，或者解析这一步根本没走线路。用 nslookup 查一次就能初步判断。

解析失败、或者解析出本机和局域网才用的地址，就是解析的问题。解决思路是让交易所域名跟着线路一起走，再按你家运营商固定一条直连线路：电信用韩国【电信直连】01，联通用韩国【联通直连】01，移动用韩国【移动直连】01。

为什么会出现「App 能用、网页不行」

打开一个网址分两步：先把域名换成 IP 地址（DNS 解析），再连这个地址。App 和浏览器在这两步上不一定一样：

  • 域名不一定相同。 App 连的接口域名，和你在浏览器里输入的主站域名，可能各不相同。某个域名被解析错了，只影响用到它的那一边。
  • 解析的地方不一定相同。 浏览器有自己的 DNS 缓存，Chrome 还有「安全 DNS」开关，电脑系统也有缓存。App 走的是手机系统的解析。
  • 走不走线路不一定相同。 线路客户端开着，App 的连接进了线路，浏览器的域名却可能先在本地解析，拿到的是本地网络给的结果。

所以「App 能用」只说明交易所本身没挂、你的账户能连，浏览器那一步拿到的地址对不对，还要另看。如果网页给的是「IP 受限」「地区不支持」这类明确提示，或者 App 也一起打不开，那就不属于本文说的情况，先看 交易所打不开、网络异常：先判断是线路还是平台。

三个信号：多半是解析出了问题

你看到的 说明什么
浏览器提示找不到服务器 IP 地址、域名无法解析 解析这一步就失败了
页面打开了，但证书报错、内容不像交易所 很可能被解析到了别的地址，不要在这个页面登录
换个浏览器、开无痕窗口、换手机流量就好了 问题在原来那台设备或那个网络的解析上

第二种情况要特别小心。地址被带偏时，你打开的页面不一定是交易所的。币安有官方的 Binance Verify 页面，可以输入网址、邮箱、电话、Telegram 或社交账号，查它是不是币安官方的（2026-10-11 核对）。其他交易所，从官方 App 里的链接或官方公告进入主站，比搜索结果里点进去稳妥。

用 nslookup 对比两个 DNS 的结果

Windows 的命令提示符和 macOS 的终端里都能直接用 nslookup。按微软的官方说明，第一个参数是要查的域名，第二个参数是要问的 DNS 服务器，不写第二个就用电脑默认的 DNS（微软 nslookup 文档，2026-10-11 核对）。

以币安主站为例，先断开线路客户端，分别查两次：

nslookup www.binance.com nslookup www.binance.com 公共DNS地址

第一条问的是你当前网络默认的 DNS，第二条把「公共DNS地址」换成你选的某个公共 DNS 服务器的地址（各家公共 DNS 的官网都公布了地址）。

看结果时注意：nslookup 最先打印的一组 Server、Address 是你问的那台 DNS 服务器自己的地址，家里通常是路由器的 192.168 开头地址，这是正常的。要看的是下面 Non-authoritative answer（非权威应答）里 Name 对应的 Address，那才是交易所域名解析出来的地址。然后按下面三条判断：

  1. 出现全零地址，或者 127、10、192.168、172.16 到 172.31 开头的地址。 这些是本机、局域网或保留用途的地址（见 IANA 特殊用途地址表，2026-10-11 核对），不可能是交易所的服务器，解析肯定错了。
  2. 报 timed out、No response from server。 微软文档对这两个错误的解释是：DNS 服务器在规定时间和重试次数内没回应，或者那台服务器上没有在运行 DNS 服务。也就是说，解析请求根本没拿到答案。
  3. 两次结果差别很大。 大型交易所通常用 CDN，不同 DNS 给出不同 IP 是正常的，不能只凭「不一样」下结论。要结合上面两条和浏览器现象一起看。

反过来，解析出来的是一个看起来正常的公网地址，也不代表一定没问题：被带偏的结果不一定是保留地址。这时以浏览器现象为准，按后面的步骤清缓存、让域名走线路再试。

这一步要在断开线路客户端时做。连着线路时，nslookup 可能不走线路，也可能返回客户端自己分配的 198.18 开头地址，结果没有参考价值，不要拿来判断。

先清掉缓存，排除旧结果

解析错过一次，错的结果可能被缓存下来，换了网络也还在用旧地址。

  • Windows： 命令行运行 ipconfig /flushdns。微软文档写明，这个命令会清空并重置 DNS 客户端的解析缓存，用于排查名称解析问题（ipconfig 文档，2026-10-11 核对）。
  • 浏览器： 关掉所有窗口重新打开，或者先用无痕窗口试一次。欧易帮助中心的排障文章也把「用无痕模式打开」「清除浏览器缓存和 Cookie」列为步骤（原页，2026-10-11 核对）。
  • hosts 文件： 如果以前手动改过 hosts、或者装过改 hosts 的工具，检查里面有没有交易所的域名。微软文档说明，系统的 DNS 缓存会预先载入 hosts 文件里的条目，写死的旧地址会一直生效。

Chrome 的「安全 DNS」开着反而打不开

Chrome 设置里有「使用安全 DNS」，会在查找网站地址时加密查询。谷歌的帮助页写明：默认是自动模式，加密查找失败时会退回普通查找。如果选了自定义的服务商，默认不会退回，出现「找不到服务器 IP 地址」这类错误时，要检查服务商设置或者关掉安全 DNS（Chrome 帮助，2026-10-11 核对）。

所以只有浏览器打不开、其他设备都正常时，看一眼这个开关。以前填过自定义服务商的，先切回默认再试。

用线路时，让交易所域名跟着线路走

很多「连了线路、网页还是打不开」，是因为域名先在本地解析了，拿到错误地址后再交给线路去连，连的就是错的地方。

原则是：交易所的域名由线路那一端去解析，不在本地网络先解析一遍。具体在客户端里怎么设置，各个客户端的选项名称不一样，看官网帮助中心。
