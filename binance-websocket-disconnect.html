币安 WebSocket 老断开：行情推送延迟怎么查

本文原载于登月VPN 博客，内容与后续更新以原文为准。

币安 WebSocket 断开，先看规律：约 24 小时断一次，是币安的连接规则。只在晚上频繁断、恢复慢，多半是线路。按「币安规则 → 本地设备 → 线路」三段排查。

线路问题的解决办法是按你家运营商选一条直连线路固定用：电信用韩国【电信直连】01，联通用韩国【联通直连】01，移动用韩国【移动直连】01。

WebSocket 断开和「币安打不开」要分开看

币安网页和 App 上的实时价格、深度和成交明细，靠 WebSocket 推过来：连接建好后一直挂着，有新数据就推。断开时页面通常还能打开，只是价格停住、K 线不跳，过一会儿自己恢复。

如果是整个页面打不开、一直转圈或提示网络异常，那是另一类问题，看 币安打不开、提示网络异常怎么办。

第一段：先对照币安自己的断开规则

币安现货 WebSocket 行情文档写明了这些规则（2026-10-11 核对 币安官方文档）：

规则 文档写法 对你意味着什么
连接时长 单个连接只保持 24 小时，到点断开 挂一整天的程序，每天必然断一次，要能自动重连
心跳 服务器每 20 秒发一次 ping，一分钟内收不到 pong 就断开 自己写的程序没回 pong，会每隔约一分钟断一次
消息频率 客户端每个连接每秒最多向服务器发 5 条消息（含 ping、pong、订阅/取消订阅） 订阅请求发太快会被断开，反复被断的 IP 可能被封
连接次数 每个 IP 每 5 分钟最多 300 次连接 重连写成死循环、不加间隔，会撞上这个上限
服务器维护 服务器要关闭前会推送 serverShutdown 事件，随后断开 收到这个事件就该马上新建连接
订阅数量 单个连接最多 1024 个数据流 订阅过多要拆成多个连接

对照方法很简单：把每次断开的时间记下来。间隔接近 24 小时，或者断之前收到过 serverShutdown，都是正常规则，自动重连就行，不用换网络。

用网页和 App 看盘的人碰不到心跳和订阅频率这几条，App 会自己处理。这两条主要针对自己写程序、用量化工具的人。

第二段：排除本地网络和设备

币安规则对不上，再看你这一端。下面几种情况，换线路也解决不了：

  • 电脑或手机休眠。 屏幕关闭、App 切到后台后，系统会限制网络，回来时行情要重新连。看盘时把节能设置调松。
  • Wi-Fi 信号弱或在两个热点间切换。 换成网线或靠近路由器，再看还断不断。
  • 客户端在几个节点之间自动跳。 开着「自动选择」「负载均衡」时，出口一换，原来的连接就断了。固定一条线路，设置方法见 帮助中心。
  • 程序本身的问题（写程序的人看）：没回 pong、重连没加等待时间、单个连接订阅太多。按上面那张表逐项改。

一个快速对照：手机关掉 Wi-Fi，用流量连同一条线路，打开币安同一个交易对。手机也跟着断，多半是币安那边或这条线路。只有家里宽带断，先查路由器和 Wi-Fi，再看第三段。

第三段：判断是不是线路的问题

前两段都排除后，满足下面的特征，基本可以确定是线路：

  1. 只在晚上 8 点到 11 点频繁断，白天正常。 这是晚高峰跨境线路拥堵的典型表现。
  2. 断开没有规律，几分钟一次，和 24 小时、心跳间隔都对不上。
  3. 推送明显变慢但没断：价格跳动比平时慢一拍，深度一阵一阵地更新。
  4. 换一条线路同时对照，那边正常。

记录时把日期、时段、运营商、断了几次、每次多久恢复写下来，连记三晚再下结论。完整的记录表和看法见 测速快不等于行情稳：看盘断线和延迟怎么测。

写程序接行情的人：两点补充

  • 端口和地址。 币安文档列了两个端口：wss://stream.binance.com:9443 和 :443。断线严重时，用两个端口各连一次对照，能帮你判断是不是某个端口的连接有问题。另有 wss://data-stream.binance.vision，只推行情，不推账户数据。
  • 断线后的数据补齐。 按币安文档维护本地订单簿时，推送的更新编号如果接不上，说明中间漏了消息，要丢掉本地订单簿，重新取快照再接着更新。只重连不重建，订单簿会和实际对不上。

程序要全天候在线，比如自动交易或需要 API 白名单的场景，放云服务器上更合适，两种做法的比较见 交易所 API 白名单：用云服务器还是固定出口线路。
