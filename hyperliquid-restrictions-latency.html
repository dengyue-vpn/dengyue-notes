延迟卡在哪一段

从你的电脑到 Hyperliquid，可以拆成两段：

  1. 你家 → 线路服务器：经过国内运营商和跨境出口，晚高峰拥堵主要发生在这里。
  2. 线路服务器 → Hyperliquid 的 API 入口：服务器在境外机房，这一段通常很短。

所以选线主要看第一段：同一个地区的线路，给电信优化的和给联通优化的，晚上表现可能差很多。这也是登月VPN 的线路按运营商分开命名的原因。

延迟怎么看

看对时间。 白天几乎所有线路都快，比较要放在晚上 8 点到 11 点。

看对指标。 测速软件的 ping 值只是一个小包来回的时间。看盘稳不稳，还要看行情连接会不会断、断了多久恢复。

看对方法。 可以这样自己测：

  • 连上线路，在 Hyperliquid 交易页盯一个你常看的合约，晚高峰盯一小时，记下行情停住的次数和每次多久恢复。
  • 同时用测速工具对线路测 ping 和 TCP 延迟，看晚上和白天差多少。
  • 连续测 3 晚，再决定这条线路合不合适。

举例：假设某条线路白天 ping 40ms、晚上 21:00 后升到 150ms 并开始偶尔停顿，那就是晚高峰拥堵。换一条给你家运营商的直连线路再测一次对比。

完整的测法和记录表见 看盘断线和延迟怎么测。

测速快，下单不一定快。 你点下单到成交，要经过交易所内部处理，用户侧测不出来。TCP 连接时间不能当成下单延迟。

官方开发文档里的连接规则

Hyperliquid 网络相关的说明在开发者文档里。以下两页 2026-10-11 核对，页面未写更新日期。

WebSocket 超时和心跳（Timeouts and heartbeats）：服务器如果 60 秒内没有给某个连接发过消息，就会关掉它。订阅的频道不是每 60 秒都有数据时，客户端可以发 { "method": "ping" }，服务器回 { "channel": "pong" }，用来保持连接。

限频（Rate limits and user limits）：以下限制按 IP 地址计算：

项目 上限
REST 请求权重 每分钟合计 1200
WebSocket 连接数 最多 10 个
新建 WebSocket 连接 每分钟最多 30 个
WebSocket 订阅数 最多 1000 个
通过 WebSocket 发出的消息 所有连接合计每分钟最多 2000 条

另有按账户地址计算的限制，和交易量挂钩，与 IP 无关。

这对普通用户意味着什么：

  • 网页看盘时偶尔断开又自动连上，可能是网络抖动，也可能是长时间没数据被服务器按 60 秒规则关掉后重连。判断要看断开的频率和多久恢复，不能只看一次。
  • 限频按 IP 计。按字面理解，同一个出口 IP 上的所有请求共用这些额度。手动看盘一般用不满。如果你跑程序、开多个连接，要考虑出口 IP 是不是多人共用。登月VPN 每条线路的出口 IP 固定，不在多个国家之间自动切换，这个 IP 由多位用户共用，适合手动交易和轻量 API。长期跑程序怎么选，见 交易所 API 白名单：云服务器还是固定出口线路。
